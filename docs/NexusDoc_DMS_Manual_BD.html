Manual de Base de Datos y Consultas SQL

Este documento describe la estructura completa de la base de datos de NexusDoc DMS, las relaciones entre tablas, y ejemplos prácticos de consultas SQL para administración y soporte.

1 Resumen del Esquema

TablaDescripciónRegistros clave
UsersUsuarios del sistema (admin y clientes)email, role, status, uniqueCode
FormDataDatos de TODOS los formularios (JSONB)userId, formType, data, userUniqueCode
DocumentTemplatesPlantillas PDF para llenado automáticoname, fileData (BYTEA)
TemplateFieldSchemasMapeo de campos PDF ↔ formulariotemplateName, acroFields, fieldMapping
UserDocumentsDocumentos personales subidosuserId, filename, fileData
SignedDocumentsFormularios firmados subidosuserId, filename, signatureStatus
AuditLogsBitácora inmutable de accionesaction, userId, description
PendingRegistrationsRegistros temporales (pre-verificación)email, code, codeExpiresAt

2 Relaciones entre Tablas

Users es la tabla central. Todas las relaciones son 1:N (un usuario tiene muchos registros):

Users → FormData (userId) — Formularios del usuario
Users → UserDocuments (userId) — Documentos personales
Users → SignedDocuments (userId) — Documentos firmados
Users → AuditLogs (userId) — Registro de actividad

Tablas independientes: DocumentTemplates, TemplateFieldSchemas, PendingRegistrations

4 Flujo de Datos

#AcciónTablas involucradas
1Usuario se registra (onboarding)PendingRegistrations → Users
2Admin aprueba cuentaUsers (pending → authorized) + AuditLogs
3Usuario llena un formularioFormData (data JSONB)
4Usuario descarga PDFFormData + DocumentTemplates + TemplateFieldSchemas
5Usuario sube documento firmadoSignedDocuments
6Usuario sube documento personalUserDocuments
7Admin consulta trámitesFormData + Users (JOIN)
8Toda acción se registraAuditLogs

5 Consultas SQL — Ejemplos Prácticos

Nota: Estas consultas se ejecutan desde el SQL Editor de Supabase (Dashboard → SQL Editor). Los nombres de tabla usan comillas dobles porque Sequelize los crea en PascalCase.

5.1 — Consultas de Usuarios

Listar todos los usuarios con su estado:

SELECT "id", "name", "email", "role", "status", "idNumber",
       "uniqueCode", "nationality", "createdAt"
FROM "Users"
ORDER BY "createdAt" DESC;

Buscar usuario por cédula / identificación:

SELECT "id", "name", "email", "role", "status", "idNumber", "uniqueCode"
FROM "Users"
WHERE "idNumber" = '8-888-1234';

Buscar usuario por nombre (parcial, sin importar mayúsculas):

SELECT "id", "name", "email", "status", "idNumber"
FROM "Users"
WHERE "name" ILIKE '%pedro%';

Buscar usuario por correo electrónico:

SELECT *
FROM "Users"
WHERE "email" ILIKE '%ejemplo@empresa%';

Ver usuarios bloqueados:

SELECT "name", "email", "idNumber", "loginAttempts", "updatedAt"
FROM "Users"
WHERE "status" = 'blocked';

Ver usuarios pendientes de aprobación:

SELECT "name", "email", "nationality", "initialForm", "createdAt"
FROM "Users"
WHERE "status" = 'pending'
ORDER BY "createdAt" DESC;

Contar usuarios por rol y estado:

SELECT "role", "status", COUNT(*) AS total
FROM "Users"
GROUP BY "role", "status"
ORDER BY "role", "status";

5.2 — Consultas de Formularios

Todos los formularios con nombre del usuario:

SELECT f."id", f."formType", f."userUniqueCode",
       u."name" AS usuario, u."email", u."idNumber",
       f."createdAt"
FROM "FormData" f
JOIN "Users" u ON f."userId" = u."id"
ORDER BY f."createdAt" DESC;

Formularios de un usuario por cédula:

SELECT f."formType", f."userUniqueCode", f."createdAt",
       f."data"->>'beneficiaryName' AS beneficiario
FROM "FormData" f
JOIN "Users" u ON f."userId" = u."id"
WHERE u."idNumber" = '8-888-1234'
ORDER BY f."createdAt" DESC;

Formularios por nombre de usuario:

SELECT f."formType", f."userUniqueCode", f."createdAt",
       u."name", u."email"
FROM "FormData" f
JOIN "Users" u ON f."userId" = u."id"
WHERE u."name" ILIKE '%juan carlos%';

Formularios por tipo (ej: solo Corporaciones):

SELECT f."userUniqueCode", u."name", u."idNumber",
       f."data"->>'companyNames' AS empresas,
       f."createdAt"
FROM "FormData" f
JOIN "Users" u ON f."userId" = u."id"
WHERE f."formType" ILIKE '%corporaci%'
ORDER BY f."createdAt" DESC;

Buscar formulario por nombre de empresa (dentro del JSONB):

-- Busca en el campo JSONB data donde companyNames contenga "Panama Global"
SELECT f."userUniqueCode", u."name", u."email",
       f."data"->>'companyNames' AS empresas,
       f."createdAt"
FROM "FormData" f
JOIN "Users" u ON f."userId" = u."id"
WHERE f."data"::text ILIKE '%panama global%';

Buscar beneficiario en formularios de Fondos:

SELECT f."userUniqueCode", u."name",
       f."data"->>'beneficiaryName' AS beneficiario,
       f."data"->>'country' AS pais,
       f."data"->>'address' AS direccion
FROM "FormData" f
JOIN "Users" u ON f."userId" = u."id"
WHERE f."formType" ILIKE '%fondos%'
  AND f."data"->>'beneficiaryName' ILIKE '%pedro%';

Contar formularios por tipo:

SELECT "formType", COUNT(*) AS total
FROM "FormData"
GROUP BY "formType"
ORDER BY total DESC;

5.3 — Consultas de Permisos y Seguridad

Ver administradores del sistema:

SELECT "name", "email", "status", "createdAt"
FROM "Users"
WHERE "role" = 'admin';

Usuarios con sesión activa (conectados):

SELECT "name", "email", "role"
FROM "Users"
WHERE "activeToken" IS NOT NULL;

Últimos intentos de login fallidos:

SELECT "name", "email", "loginAttempts", "status", "updatedAt"
FROM "Users"
WHERE "loginAttempts" > 0
ORDER BY "loginAttempts" DESC;

Bitácora de auditoría por usuario:

SELECT a."action", a."description", a."createdAt",
       u."name", u."email"
FROM "AuditLogs" a
LEFT JOIN "Users" u ON a."userId" = u."id"
ORDER BY a."createdAt" DESC
LIMIT 50;

Acciones de un usuario específico:

SELECT a."action", a."description", a."createdAt"
FROM "AuditLogs" a
JOIN "Users" u ON a."userId" = u."id"
WHERE u."email" ILIKE '%ejemplo@empresa%'
ORDER BY a."createdAt" DESC;

5.4 — Consultas de Documentos

Documentos firmados por usuario:

SELECT s."filename", s."signatureStatus", s."createdAt",
       u."name", u."email"
FROM "SignedDocuments" s
JOIN "Users" u ON s."userId" = u."id"
ORDER BY s."createdAt" DESC;

Documentos con firma pendiente:

SELECT s."filename", u."name", u."email", s."createdAt"
FROM "SignedDocuments" s
JOIN "Users" u ON s."userId" = u."id"
WHERE s."signatureStatus" = 'Firma Pendiente';

Documentos personales de un usuario por cédula:

SELECT d."filename", d."createdAt"
FROM "UserDocuments" d
JOIN "Users" u ON d."userId" = u."id"
WHERE u."idNumber" = '8-888-1234';

5.5 — Consulta Maestra: Resumen completo de un usuario

-- Reemplazar 'ejemplo@empresa.com' por el correo del usuario

-- 1. Datos del usuario
SELECT "name", "email", "role", "status", "idNumber",
       "uniqueCode", "nationality", "createdAt"
FROM "Users"
WHERE "email" ILIKE 'ejemplo@empresa.com';

-- 2. Sus formularios
SELECT f."formType", f."userUniqueCode", f."createdAt"
FROM "FormData" f
JOIN "Users" u ON f."userId" = u."id"
WHERE u."email" ILIKE 'ejemplo@empresa.com';

-- 3. Sus documentos firmados
SELECT s."filename", s."signatureStatus", s."createdAt"
FROM "SignedDocuments" s
JOIN "Users" u ON s."userId" = u."id"
WHERE u."email" ILIKE 'ejemplo@empresa.com';

-- 4. Su actividad en bitácora
SELECT a."action", a."description", a."createdAt"
FROM "AuditLogs" a
JOIN "Users" u ON a."userId" = u."id"
WHERE u."email" ILIKE 'ejemplo@empresa.com'
ORDER BY a."createdAt" DESC LIMIT 20;

5.6 — Operaciones Administrativas (usar con precaución)

Precaución: Estas consultas modifican datos. Ejecutar solo en el SQL Editor de Supabase con confirmación.

Desbloquear un usuario:

UPDATE "Users"
SET "status" = 'authorized', "loginAttempts" = 0
WHERE "email" ILIKE 'usuario@empresa.com';

Cambiar rol de un usuario a admin:

UPDATE "Users"
SET "role" = 'admin'
WHERE "email" ILIKE 'usuario@empresa.com';

Cerrar todas las sesiones (logout global):

UPDATE "Users"
SET "activeToken" = NULL;
